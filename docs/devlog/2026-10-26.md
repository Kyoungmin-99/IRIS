# 2026-10-26 개발일지

## 네일 '내 손톱 찾기' 9/25 → 24/25(손톱 전용 모델) · 타투 손등·글자 빠짐 · 타투 잉크 모델 직접 학습 시작 · 코덱스 손 사진 194장

새벽에 "네일도 너가 해결해", 낮에 사용자가 직접 찍은 **손 사진 5장**을 보내 주며 "네일아트 부분 좀 어떻게 해 봐, 필요한 모델이라도 더 찾아서",
저녁에 "**90점 이상으로 완성**, 수단과 방법을 가리지 말고, 모델이 필요하면 구하고, 필요한 정보는 바로 말해 달라(GPU 없이)"는 요청을 받았다.
필요한 사진은 코덱스가 모으기로 해서, 손 사진·팔·얼굴 사진의 구체적인 수집 요청(프롬프트)을 써 주었다. AI 저장소는 사용자가 비공개로 바꿨다.

### 문제와 해결
- **회귀 시험 방법**: 바꾼 빌드(4173·4176)와 직전 커밋 빌드(4174)를 손 사진 11~13장, 타투 24장으로 나란히 돌려 픽셀 차이·확대 그림으로 비교. 대부분 0픽셀, 바뀐 곳만 눈으로 확인.
- **되돌린 시도**: 다시 오릴 때 점을 손가락 끝 쪽으로 옮기고 손 점 손톱 넓이에 가장 가까운 후보를 고르기 — h67 은 좋아졌지만 h68·h69 가 5 → 3 개로 나빠져 되돌림. 누드 고른 사진에 SAM 격자 쓰기 — 누드 핑크는 4개 정확, 연핑크는 손가락 피부를 잡아 보류.
- **'ner' 원인 찾기**: 얼굴 지우기·조각 지우기·분할 피부를 차례로 의심했다가, 브라우저에서 뽑은 분할 자료로 `extractDesign` 을 node 로 다시 돌려 열마다 잉크를 세어 '잉크 찾기 단계에서 이미 0' 을 확인 → 윤곽선 판정이 원인.
- **시간 문제**: 컨테이너가 두 번 재시작돼 미리보기 서버를 다시 띄움. CPU 학습과 브라우저 시험이 서로 느리게 만들어 학습 중에는 브라우저 시험을 멈춤. 학습은 세션 시간 제한을 피하려 분리 실행.
- **사진 수집**: 사용자가 "코덱스는 핀터레스트·인스타그램에서 모아 주는데 왜 못 하냐"고 물음 → 약관(자동 수집 금지)과 공개 저장소 재배포 문제를 설명하고, 직접 모은 사진은 비공개 저장소에, 자유 라이선스 수집은 보조 에이전트로 진행.

### 결정 사항
- 손이 잡히면 손톱은 **손톱 전용 모델을 먼저**, 못 찾은 손가락만 SAM.
- 타투 잉크는 **합성 자료로 직접 학습한 모델**을 규칙(밝기 대비)에 더하는 방식으로 쓴다(규칙을 버리지 않고, 모델이 없으면 규칙만).
- 사진 모드는 GPU 없이(브라우저·CPU) 간다. AnyDoor 는 CPU 로 최대한.
- 코덱스 수집 사진은 비공개 AI 저장소 `photo-collection` 브랜치에, 학술 목적 라이선스(11k Hands 79장)는 시험에만.

### AI 도구 활용
- Claude Code: 사용자 손 사진으로 결함 재현 → 단계별 기록(judge·tipc) → 원인 → 수정 → 빌드 둘로 나란히 회귀 → 커밋·handoff / 합성 자료 생성기·학습 스크립트 작성과 CPU 학습 / 실제 사진으로 모델 확인 / 코덱스 수집 요청서 작성 / 저장소 감시(5분마다)로 업로드 즉시 받기.
- 공개 모델: SlimSAM, MediaPipe 손·포즈·분할, BiSeNet 얼굴 분할, AI 저장소 손톱 분할 모델(자체 학습), 스타일 AI. 코덱스(사진 수집), 보조 에이전트(자유 라이선스 사진 수집).
